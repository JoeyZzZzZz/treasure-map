# Treasure Map vendor watchlist — EXAMPLE TEMPLATE (committed, brand-free).
#
# Brand names are kept out of the repository: the full denylist is a local file,
# never committed. Point the hook at it with the TM_VENDOR_WATCHLIST env var; the
# local copy may also live git-ignored at .githooks/vendor-watchlist.txt.
#
# The pre-commit hook uses the full local list if present, else falls back to
# this template (generic model-number patterns only, plus the human reviewer).
#
# Vendor-specific daemon/binary names (e.g. a brand's main web service binary)
# are NOT regex-detectable without false positives — add those literal names to
# your local list, not to this committed template.
#
# One pattern per line; '#' and blank lines are ignored.
# Lines starting with [ or ( are treated as PCRE regex (case-sensitive).
# All other lines are treated as literal patterns (case-insensitive, whole-word).

# Model-number patterns (generic; require a digit so plain UPPERCASE-HYPHEN
# words like WIPE-AND-REBUILD do not false-positive; standard names such as SHA-256,
# UTF-8 or CVE ids are let through). The second is a one- or
# two-letter uppercase prefix run into four or five digits; three-digit forms are
# left to the local list, because lint codes (S608, E501, ...) share that shape; shellcheck
# codes (SC followed by four digits) are let through.
(?<![A-Za-z])(?!(?:SHA|MD|CRC|UTF|ISO|RFC|CVE)-)[A-Z]{2,4}-(?=[A-Z0-9]*[0-9])[A-Z0-9]{2,6}[LWHABM]?
(?<![A-Za-z0-9_])(?!SC[0-9]{4}\b)[A-Z]{1,2}[0-9]{4,5}(?![A-Za-z0-9_])

# Lower-case run-together model form: a >=2-letter prefix immediately followed by
# >=3 digits and an optional single trailing letter (e.g. an IoT camera model
# written all-lowercase, no hyphen, with or without a suffix letter). The leading
# (?i) makes it case-insensitive; the negative lookahead whitelists common
# technical tokens of the same shape (hashes, charsets, int/float widths, arch and
# OS tags, interpreter tags like py3xx, key/curve/cipher sizes such as ed25519 /
# aes256 / rsa2048, port numbers, lint rule codes, this project's own fn<id> refs
# and test placeholders) so they are NOT flagged. >=3 digits is required so
# 2-digit tech words (base64, arm32, crc32, int64, ...) never reach the regex at
# all. A one-letter prefix or an underscore-joined form is left to the local list:
# a generic one-letter lowercase rule would also match tokens like ed25519.
(?i)\b(?!(?:sha1|sha224|sha256|sha384|sha512|sha3|md4|md5|crc8|crc16|crc32|crc64|base32|base64|utf8|utf16|utf32|int8|int16|int32|int64|int128|uint8|uint16|uint32|uint64|float16|float32|float64|ipv4|ipv6|arm32|arm64|aarch64|x86|mips32|mips64|win32|win64|py3[0-9]{2}|ed25519|curve25519|aes(?:128|192|256)|rsa(?:1024|2048|3072|4096)|poly1305|port[0-9]+|fn[0-9]+|abc[0-9]+|foo(?:bar)?[0-9]+|aabb[0-9]+|secret[0-9]+|(?:sc|up|try|sim|pth|ble|arg|plr|plw|plc|ple|ruf|ann|fbt|ptc)[0-9]{3,4})\b)[a-z]{2,6}[0-9]{3,}[a-z]?\b
